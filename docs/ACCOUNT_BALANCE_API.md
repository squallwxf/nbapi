# API Key 账户余额接口

状态：2026-10-07 已部署；本地及服务器隔离环境55项回归通过。线上验证真实Key余额、无费用/额度消费、匿名拒绝及禁止缓存通过。

## 请求

`GET https://nbapi.win/v1/account/balance`

请求头：`Authorization: Bearer <用户的 nb_sk_ API Key>`。
兼容现有 `X-NBAPI-Key` 请求头，不允许把密钥放在URL。
不需要网站登录会话，不接受客户端指定账户；额外查询参数不会改变所属账户。

## 成功响应

```json
{"balance":"12.345678","currency":"CNY"}
```

`balance` 是所属账户余额的十进制字符串，保留六位小数；不是该Key的剩余额度。
币种沿用网站现有人民币显示口径，不进行汇率换算。
余额可以为零或负数。Key额度耗尽或模型白名单不影响余额查询，调用模型仍受原有限制。

## 错误与限制

- 401：`api_key_required` 或 `invalid_or_inactive_api_key`；包括过期/禁用密钥或禁用账户。网站登录凭证不能替代API Key。
- 403：`ip_not_allowed`，沿用现有IP/CIDR校验。
- 429：`rate_limited`，专用余额查询桶按来源IP限制10次/60秒，包含 `Retry-After: 60`。与登录/注册限流桶分离。
- 成功及以上错误响应均包含 `Cache-Control: no-store`。

查询不调用供应商，不产生费用、预扣、账单或额度消费。复用现有鉴权会更新Key的 `last_used_at`；不新增数据库结构。
不要记录请求认证头或完整密钥。余额只返回金额与币种，不返回身份信息或其他账户数据。

## NB画布接入

填写或切换Key后查询；切换时立即清除旧余额，避免慢请求覆盖新Key的状态。
支持手动刷新和生成结束后刷新；对429遵守重试时间，不高频轮询。
失败显示“查询失败”而不是零余额。界面可显示两位小数，但内部保留原始值。
余额及密钥不得写入画布文件；沿用现有安全凭证存储。只向用户配置的可信HTTPS网关发送Key。
